# Canon AT-1 真实拆解体验设计

**日期：** 2026-08-31  
**状态：** 已获方向授权，直接实施  
**范围：** Teardown 目录页、Canon AT-1 拆解实验室、移动端可用性、与真实性直接相关的安全收口

## 1. 问题定义

当前产品把 12 台相机都呈现为可进入的“3D 拆解”，但资产事实并不支持这个承诺：

- Canon AT-1 的 GLB 只有 6 个独立 mesh，可做有限的真实外观分件。
- Hasselblad 500cm 的 GLB 是单一 mesh，无法形成零件级爆炸。
- 其余 10 台没有真实 3D 资产，页面用 box/cylinder 等程序化几何体代替零件，因此与真实相机结构差异很大。
- 运行时 AI 会依据原始 mesh 名“猜”零件含义和 OEM 编号，既不可验证，也会在接口不可用时让核心体验失效。
- 手机端返回键、缩放控件和爆炸滑块相互争抢空间，关键操作会被裁切或遮挡。

根因是内容状态与资产能力没有建模，而不是爆炸距离或材质参数不够精致。

## 2. 产品目标

一期只让 Canon AT-1 进入拆解实验室，其余 11 台保留为资料卡并标注“拆解制作中”。

Canon AT-1 页面提供两种互补但不混淆的内容：

1. **真实 3D 分件：** 只控制 GLB 中真实存在的 6 个 mesh，不生成虚构零件。
2. **结构导览：** 根据维修资料讲解顶/底盖、电气单元、卷片与快门、反光镜箱等机构，并明确说明这些内部机构当前没有在 3D 模型中呈现。

成功标准：

- 用户无法再进入积木式假拆解页。
- Canon AT-1 的爆炸方向稳定、可复现，不因刷新而随机飞散。
- 所有零件解释来自本地审核过的静态内容；不再请求 AI 猜测。
- 手机 390×844 下可以返回、切换章节、拖动拆解进度、查看零件说明，控件不重叠。
- 模型加载失败时给出诚实错误提示，不回退到程序化积木。
- 页面展示原 3D 作者和 CC BY 4.0 署名链接。

## 3. 内容架构

### 3.1 目录页

每张相机卡拥有显式状态：

- `live`：Canon AT-1；使用可聚焦的按钮语义，显示“进入真实拆解”。
- `coming-soon`：其余机型；使用资料卡语义，显示“资料卡 · 拆解制作中”，不可进入实验室。

搜索同时匹配品牌、型号和技术关键词。没有结果时保留清晰空状态。

### 3.2 Canon AT-1 实验室

实验室分为四个导览章节，章节与拆解进度同步：

1. **整机基准（0%）**：观察机身比例和操控布局。
2. **外部操控（32%）**：分离电池检测、过片、快门释放与快门速度控制等真实 mesh。
3. **胶片路径（66%）**：突出卷轴与机身关系，同时用结构导览解释胶片推进路径。
4. **维修边界（100%）**：完全展开现有 mesh，并列出当前 3D 未呈现的内部机构。

章节不是伪装成精确 CAD 的内部视图。它是一份带证据边界的维修结构地图。

### 3.3 零件说明

每个真实 mesh 使用人工维护的双语说明：

- 显示名称；
- 在整机中的作用；
- AT-1 语境下的限制或注意事项；
- 证据标签：`真实 3D 分件` 或 `模型命名待核对`；
- 不展示无法验证的 OEM 零件号。

用户既可以点击 3D mesh，也可以通过可键盘操作的零件列表选择零件。

### 3.4 来源与边界

页面底部固定提供：

- 3D 资产：AleixoAlonso 的 Canon AT-1 Retro Camera，CC BY 4.0；
- 结构参考：Canon AT-1 Repair Guide / Service Manual 的外部入口；
- 明示声明：当前模型不是维修级 CAD，内部机构未在 3D 中完整呈现。

不复制或重新分发维修手册页面。

## 4. 交互与视觉方向

视觉采用“1970 年代维修台档案”方向：炭黑工作台、泛黄纸张、机械红橙色标记、细线网格和编号标签。避免蓝紫霓虹、玻璃拟态和通用 AI 控制台风格。

### 桌面端

- 顶部：品牌、语言切换、返回目录。
- 左侧：章节导览与结构边界说明。
- 中央：真实 3D 模型。
- 右侧：选中零件说明。
- 底部：单一拆解进度控制，不再提供与 OrbitControls 重复的独立缩放组件。

### 手机端

- 顶部压缩为两行以内，返回按钮始终在安全区内。
- 章节改为横向可滚动的编号标签。
- 拆解滑块固定在底部安全区上方。
- 零件说明以可滚动底部面板呈现，不覆盖返回按钮。
- 触控目标不小于 44×44 CSS 像素。

## 5. 技术设计

### 数据层

`CameraModel` 增加 `availability`、`availabilityNote` 和可选 `attribution`。只有 `live` 且存在 `modelUrl` 的机型允许进入实验室。

`CameraPart` 移除程序化几何必需字段，改为真实 mesh 映射、确定性爆炸方向和本地双语知识内容。

新增 `TeardownChapter`，把进度、标题、说明、相关零件和表示方式固化为数据，避免 UI 自行猜测。

### 3D 层

- 预先遍历并缓存 mesh 条目，不在每一帧遍历整棵 scene tree。
- 初始化时复制材质，避免选中状态污染共享 GLTF 资源。
- 只使用人工定义的爆炸方向；未映射 mesh 保持原位。
- 每帧复用向量与颜色，不创建临时对象。
- 加载失败只显示错误状态，不创建程序化替代模型。

### 内容层

- 移除 `geminiService` 的运行时调用和客户端 API Key 注入。
- 静态说明成为首屏即可用的产品内容，不依赖配额、网络或模型响应。
- 移除未使用的 `@google/genai` 依赖。

### 样式层

- 移除 Tailwind CDN 和 import map。
- 新建实际存在的 `index.css`，使用语义类名、CSS Grid/Flex 和媒体查询完成布局。
- 3D 实验室通过 `React.lazy` 延迟加载，目录页不立即解析 Three.js 场景代码。

## 6. 测试与验收

自动化测试覆盖：

- 只有 Canon AT-1 是 `live`；
- 不可用资料卡不能被解析为可进入实验室；
- Canon 的 6 个 mesh 映射均有确定性方向和静态说明；
- 章节进度严格递增并覆盖 0–100；
- 进度可以稳定映射到正确章节；
- UI 文案不再包含 AI 猜测或 OEM 编号承诺。

工程验证：

- TypeScript 类型检查；
- Vitest 全量测试；
- Vite 生产构建；
- `npm audit --omit=dev`；
- Playwright 在 1440×900 与 390×844 检查目录、资料卡、实验室关键操作、控制台错误和网络失败状态。
